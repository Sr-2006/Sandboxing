### Key Architectural Guarantees for Phase 2 / Phase 3

1. **Incident Identifier**:
   - `incident_id` is always a unique composite string formatted as `<target_service>_<cluster_id>` (e.g. `payment-service_12`, `order-service_15`). Never a random UUID.
2. **Prioritization & Sorting**:
   - The `incidents` array is pre-sorted in descending order by `priority_score`.
   - Priority scores account for occurrence velocity ($\log_{10}$ scale), container failure state penalties ($+50$ for exited/dead, $+30$ for unhealthy), statistical anomaly penalties ($\le 25$), and exponential time decay ($\le 20$).
3. **Telemetry Evidence**:
   - `log_cluster_template`: Sanitized Drain3 template derived from multi-line stitched exception blocks. The template ALWAYS contains the exception class and first error message (e.g. `java.lang.NullPointerException: X`), NEVER a standalone `at <*>` line.
   - `log_samples`: Contains up to 5 most recent unmasked log records with preserved stack traces, log levels, and populated OpenTelemetry `trace_id` / `span_id` (target $\ge 80\%$ correlation for ERROR/WARN logs).
   - `metrics_snapshot`: Contains up to 3 most recent host container metric points. If empty (for fresh-cluster incidents), Phase 2 indexers must gracefully handle `[]` without erroring.
4. **ChromaDB Vector Fingerprinting Contract**:
   - Phase 2 vector embedding key is mandated to be the `(target_service, log_cluster_template)` tuple.
   - `trace_id` MUST be indexed as metadata for cross-span trace correlation across microservices.
   - Validation rule: Any incident entry with an empty or blank `log_cluster_template` MUST be filtered out prior to ChromaDB indexing.
5. **State Versioning & Reset Policy**:
   - Running `python phase1_processor.py --reset-drain` is a destructive but expected operation for version 2 state migration. It resets `drain3_state.bin` to ensure clean, non-divergent cluster IDs after pre-stitcher logic changes.
6. **Chaos Context**:
   - `active_infrastructure_mutations` contains active faults when incidents overlap with a known scenario from `chaos_history.json` within $\pm 5$ minutes, or `""` if no mutations were active.
